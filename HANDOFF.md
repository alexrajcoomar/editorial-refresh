# Handoff: alexrajcoomar.github.io

Written for the Claude Code session that will redesign this site. Everything
below was verified against the actual files on 23 August 2026. Read this
before touching anything.

## What this site is

A static portfolio for Alex Rajcoomar, a University of Waterloo Accounting
and Financial Management (Analytics) student, live at
https://alexrajcoomar.github.io (GitHub Pages, `main` branch, repo root).
Its brand is auditability: the headline is "I make arguments you can
audit", every number on the site is measured rather than estimated, and the
site proves it with a self-checking build. The audience, in order: a
recruiter screening an AFM student in about thirty seconds, then a
technical interviewer who clicks deeper, then Alex himself, who studies
from this material daily.

## Architecture in one paragraph

There is no framework, no bundler, and no client-side dependency; the
footer's claim "hand-written HTML and CSS, no framework" is true and is
part of the product. One Python generator, `build/build_site.py` (with
`build/atlas.py`), regenerates the nine shell pages from `content/*.json`
and injects shared chrome into the 61 standalone piece files. GitHub
Actions (`.github/workflows/build.yml`) reruns it on every push: it
measures changed pieces in headless Chromium (`build/measure_plan.py`,
`build/measure.js`), redraws stale link-preview cards (`build/cards.js`
into `cards/`), rebuilds, runs the checks, and commits the result back with
`[skip ci]`. The build fails on any broken link, bad canonical, missing
icon, or page using a glyph the self-hosted font subset lacks.

## The two kinds of HTML — do not confuse them

**Shell pages** (index, research, coursework, tools, library, atlas, about,
colophon, 404) are GENERATED. Never edit them directly; edit
`build/build_site.py` and rebuild (`python3 build/build_site.py`; run it
twice — the second run must print "rewrote: nothing").

**Piece pages** (the other ~66 root HTML files) are CONTENT. Each is a
standalone, self-contained document — essays, course references,
interactive tools — with its own internal design. The build injects three
marked blocks into them (`<!--__rb-->` return bar, `<!--__rbp-->` pill,
`<!--__meta-->` head metadata) and writes section anchor ids used by the
Atlas. Their prose, figures, provenance labels, and internal design are the
portfolio itself: restyle the site around them, do not rewrite them.

## What must keep working (break any of these and the site is worse)

1. **Every existing URL.** All ~75 root `.html` files, their `#anchors`
   (the Atlas deep-links into pieces via ids the build wrote), sitemap.xml
   and canonicals. Nothing may 404 after the redesign.
2. **The editor.** `admin.html` is how the owner (non-technical) runs the
   site: it talks to the GitHub Contents API with a fine-grained token held
   in sessionStorage only, and writes exactly one file —
   `content/pieces.json` — plus uploaded piece files. Its contract is the
   pieces.json schema: `{note, site:{name, short, email, url, born,
   headline, eyebrow, affiliation}, pieces:[{slug, t, s, k(Essay|Reference|
   Tool), surface(independent|course|personal), c, d, url, featured, pwa,
   tags[], blurb, demo}]}`. Keep the schema and the editor keeps working;
   change it and you must update admin.html in the same commit.
3. **The CI pipeline.** `python3 build/build_site.py` must remain the one
   build entry point, idempotent, exit non-zero on check failure. The
   measurement flow feeds every figure on the site (word counts, figures,
   tables in `content/metrics.json`); no figure is ever typed by hand.
4. **The Atlas** (`atlas.html` + `atlas.js` + `build/atlas.py`). 1,551
   sections of 61 documents placed on a sphere, every mark a real link; the
   page carries the data in its own DOM (works with scripts off, 1,600+
   links server-rendered); a demand-driven canvas renderer that idles at 0
   requestAnimationFrame; citation chords drawn only from links that exist
   in piece prose (`build/atlas.py edges()`); tour stages, survey, search,
   deep links. Its honesty contract: every visual channel encodes recorded
   data, named in the on-screen key; positions never move; no invented
   geometry. `atlas-concepts.md` and the design-history docs explain why.
5. **The offline layer.** `sw.js` (generated by the build): cache-first
   with background refresh, a full-site save flow driven from the colophon
   ("Keep the whole site on this phone", reads `offline-manifest.json`),
   `site.webmanifest` + icons for Add to Home Screen. Three tools
   (law-arena, skill-forge, daily-learning-cockpit) also install
   individually with their own manifests — keep both layers.
6. **The self-hosted font.** `InterVariable-sub.woff2` is subset to the
   corpus (243 codepoints); the build check names any page character the
   subset lacks. New glyphs mean re-subsetting from `inter-ui` via
   pyftsubset (command documented in build_site.py near the check).
7. **Measured claims.** The colophon defines every measurement; the home
   page stats, the Atlas lede, and the footer counts are all computed. Keep
   that property: a redesign that types a number breaks the brand.
8. **Reader privacy.** The reading trail (`localStorage["atlas.trail"]`)
   and theme choice stay in the browser and are never sent anywhere.

## Structure recommendation

Keep the home page as the landing experience, not the Atlas. This was
measured, not guessed: an earlier pass that led with apparatus before work
tested worse for the thirty-second reader, and the current order (identity
→ selected work → corpus figures → method) is the result. The Atlas is the
signature piece and belongs one click away, teased by the hero globe (same
data, same encoding, drawn small). Worth redesign attention, in order: the
home page's storytelling and first impression; the four listing pages
(research/coursework/tools/library overlap — they could consolidate to
two, or one listing with facets, provided every old URL still resolves);
piece-page chrome (the injected return bar is functional but minimal).
Leave alone unless there is a measured reason: the Atlas renderer, the
admin editor, the build checks, the colophon's definitions.

## Traps

- Editing a generated page and losing it on the next build.
- Reformatting piece HTML and destroying anchor ids, provenance labels
  (VERIFIED/INFERRED/REPRODUCED chips), or the injected block markers.
- Adding an external dependency (CDN font, script, analytics): the site
  has zero external requests, Best Practices 100 on every page, and the
  colophon says so.
- Breaking build idempotence (CI loops or churns).
- `content/metrics.json` and `content/fingerprints.json` are CI-maintained;
  hand-editing them lies about measurements until CI corrects it.
- The three PWA tools have their own manifests; injecting the site manifest
  into them double-registers (the build already skips them — keep that).
- Piece interiors legitimately differ in type and palette from the shell;
  four older pieces still load Google Fonts by the owner's choice. That is
  content, not a bug to fix silently.
